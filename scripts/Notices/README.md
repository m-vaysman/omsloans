# Mock Notices

Sample agent-bank interest accrual notices, generated by the LINQPad script at
[`tools/AccrualNoticePdfGenerator.linq`](../../tools/AccrualNoticePdfGenerator.linq).

## Everything here is fake

**No account is real. No company name is real. No bank is real.**

Borrower names, agent bank names, facility identifiers, ABA routing numbers, account
numbers, SWIFT codes, addresses, phone numbers and email addresses are all invented. Any
resemblance to an actual institution, borrower or account is coincidental — the wire details
in particular are randomly generated at build time and change on every run.

Every page carries a **COBBLER HILL DEV (MOCK)** watermark, and several templates print a
mock disclaimer in the footer as well.

## What they are for

To run realistic PDF and image notices through an AI model and get structured accrual data
back — the extraction step this system is built around.

The notices deliberately vary in layout, so extraction is tested against the kind of
inconsistency real agent banks produce rather than against one house style. The prompts that
consume them live in [`scripts/prompts/`](../prompts) — one for vision input, one for text
extracted from a PDF. Both return the same JSON schema, so results are comparable whichever
path a notice takes.

## What's in the set

20 notices, named `NN_FacilityId_Borrower_Tn.pdf`, where `Tn` is the template used.

| | |
| --- | --- |
| Agent banks | 5, four notices each |
| Layouts | 5 templates, four notices each |
| Borrowers | 20 distinct |
| Facilities | 20 distinct |
| Activity | 17 interest accrual, 3 interest + principal paydown |

The economics — rates, principal, accrued interest, periods and payment dates — are drawn
from real rows in [`scripts/MockLoanSchedule.xlsx`](../MockLoanSchedule.xlsx), so the numbers
are internally consistent and a correct extraction can be checked against a known answer.
The figures themselves are mock data; only their consistency is real.

Note that templates 3 and 4 do not print the base rate and margin as separate values —
template 3 shows the rate as a decimal factor inside a calculation, template 4 shows only the
all-in rate. Extractions from those two should return null for `base_rate` and `margin`,
which makes them useful checks that a model reports what a notice actually says rather than
inferring what it ought to contain.

## Regenerating

Open the generator in LINQPad and set `templateToUse`, or drive it in a loop. It writes to
the system temp folder by default. Wire details are re-randomised on each run, so
regenerating produces different account numbers for the same notice.
